# The messages and requests that change a drawing and make no undo step
# (see undo_record_guard.rs). One name on each line; `#` starts a comment.
# Remove a name when its handler gets an undo step. A new name needs a reason.

# By design: a live edit. The entity changes while the user draws or drags,
# and the end of the command or of the grip edit completes one undo step
# (`finish_live_entity_history`, `push_entity_group_history`).
CommandInput during PLINE
CommandOptionPick during PLINE
ContextMenuPick(Grip)
GripMenuPick
SetModifiers
ViewportLeftPressAt(Point) during PLINE

# By design: a cancelled command takes back what it placed, and a cancelled
# grip edit puts back the entity that it changed.
CommandEscape
CommandEscape during BACTION

# By design: view state. A viewport's stale saved view is corrected when
# the viewport becomes active.
EnterViewport(Handle) during ALIGNSPACE

# No undo step when the guard was added, and known then: a layout becomes
# current (the first use of a layout also adds its viewport).
LayoutSwitch

# No undo step when the guard was added, and known then: a typed command or

ScriptLine during LINETYPE

automation:run COLOR
automation:run LINETYPE
